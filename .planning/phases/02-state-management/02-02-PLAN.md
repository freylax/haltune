<objective>
Create a dedicated refresh thread that polls HAL at configurable intervals (default 100ms), enumerates ALL pins/signals/params from HAL (including newly created ones), removes stale entries for unloaded components, and updates the state cache.

Purpose: The TUI needs fresh HAL data without blocking. A background refresh thread polls HAL independently, keeping the cache current. By enumerating all pins from HAL on each cycle (not just cached pins), the refresh thread dynamically discovers pins from newly loaded components (via halcmd loadusr) and removes pins from unloaded components. TUI components read from cache, never directly from HAL.

Output: src/state/refresh.zig with RefreshThread struct managing thread lifecycle and refresh timing.
</objective>

    Pattern:

    2. refreshHal(self: *RefreshThread) !void
    - Discovery phase: Enumerate ALL pins from HAL (not just cache)
      - Call halpr_find_pin_by_name(null) to get first pin
      - Walk linked list via pin.next to enumerate all pins
      - Collect pin names and pointers into a temporary ArrayList
    - Snapshot phase: Get current cache keys using store.listPins(self.allocator)
    - Comparison phase:
      - For each HAL pin: if not in cache, add via store.addPin (newly discovered)
      - For each cache pin: if not in HAL snapshot, remove via store.removePin (stale cleanup)
    - Update phase: For each pin in HAL snapshot, read current value via ffi.getPin* and update cache
    - Repeat for signals and params using halpr_find_sig_by_name(null) and halpr_find_param_by_name(null)

    Implementation approach:
    ```zig
    // Discovery: Walk HAL's linked list
    var hal_pins = std.ArrayList(*c.hal_pin_t).init(self.allocator);
    defer hal_pins.deinit();

    var maybe_pin = ffi.halprFindPinByName(null);  // null = first pin
    while (maybe_pin) |pin| {
        try hal_pins.append(pin);
        maybe_pin = pin.*.next;  // Walk linked list
    }

    // Get cache snapshot for comparison
    const cached_names = try store.listPins(self.allocator);
    defer self.allocator.free(cached_names);

    // Find new pins (in HAL but not cache)
    for (hal_pins.items) |pin| {
        const name = std.mem.span(pin.*.name);
        if (!isInList(cached_names, name)) {
            try store.addPin(name, pin.*.type, pin.*.dir);
        }
    }

    // Find stale pins (in cache but not HAL) and remove
    for (cached_names) |cached_name| {
        var found = false;
        for (hal_pins.items) |pin| {
            if (std.mem.eql(u8, cached_name, std.mem.span(pin.*.name))) {
                found = true;
                break;
            }
        }
        if (!found) {
            try store.removePin(cached_name);
        }
    }

    // Update all current values
    for (hal_pins.items) |pin| {
        const value = try readPinValue(pin);  // ffi.getPinFloat/etc.
        try store.updatePin(std.mem.span(pin.*.name), value);
    }
    ```

    Follow RESEARCH.md Pitfall 1: Read HAL values BEFORE acquiring cache lock.

    This addresses STATE-03: Components loaded via halcmd loadusr will have their pins discovered on the next refresh cycle, and unloaded components' pins will be removed from cache.
